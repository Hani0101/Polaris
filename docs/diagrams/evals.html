What the evals cover

Evals run the real AI against the project's rules and score what it does. They are separate from the unit tests, which use a fake model. Yellow notes explain words you may not know.

agent the AI tutor, profile pass or animation writerGreen = covered by an evalDashed border = not covered yet

1. What an eval is, and how it runs

A case is one situation and a few checksEach case names the rules it tests (like PR-02 or WB-05). The default is 3 samples per case, because the model's answers vary. Rule: a numbered line in docs/features/, such as PR-02 "an empty profile is filled before teaching". Sample: one run of a case. Three samples of the same case can pass, pass and fail.
each sample gets its own sandbox
Throw-away data folderIts own empty profile and database, deleted afterwards. The learner's real data is never opened. Teaching cases run with no profile pass and no animation writer attached, so a turn cannot change the profile or start a background job.
the real agent is called
Real model through the local Claude loginNot a mock. It costs money and takes minutes, so pytest never collects it. The run stops if an API key is set (decision 0001). Run it: uv run python -m evals from api/. Options: --runs, --cases, --jobs, --list.
checks score the output
Code checks (almost all)
Plain program logic: did the tool call succeed, is the marker in the reply, does the cited page hold the claim. Cannot be talked round.
Keyword checks
Regex heuristics, named "(keyword)" in the report, for things like "asks for the three profile parts". A failure needs a look at the transcript.
One model judge
A single small-model yes/no, used only where code cannot decide: does the reply adapt to a stated struggle? The report labels it. n/a: a check that does not apply (no whiteboard drawn, so no step markers) is neither pass nor fail. Pass rate = passed / (passed + failed).
report
Written to api/evals/reports/<time>.md with raw results beside it as .json. The folder is gitignored.

3. Drawing quality evals (separate tool)

A second harness, evals/drawing_eval.py, scores how good whiteboard drawings look, not just whether they are valid. It has two modes:
scoreReads whiteboards already stored in a data folder and scores them. Never calls the model.
runSends 8 fixed prompts (water cycle, photosynthesis, mitosis vs meiosis, animal tree, cell parts, HTTP request, parabola, 2/4 = 1/2) to the tutor and scores the drawings it stores.
Layout problems counted: overlap, text spilling out of its box, parts outside the board, loose arrows, too many parts, misplaced marks. A drawing is clean when it has none. Gate: exits with status 1 when the share of clean drawings is under --min-clean, so a run can block a change such as a new layout kind. It also counts how many fixes each drawing needed.

4. Animation evals (separate tool)

A third harness, evals/run_animation_evals.py, runs 10 fixed briefs through the real writer and the animation check: pendulum, binary search, derivative as slope, attention in a transformer, bubble sort, photosynthesis, sine on the unit circle, stack push/pop, fractions as pizza, compound interest. Records: whether each job became ready, how many runs it used (AN-05 allows three), how long it took, and the last check errors. Ready animations are saved so they can be opened and judged by eye. Results go to evals/results/.

5. What is covered, and what is not

Of 168 numbered rules in docs/features/, the 14 cases touch 16. They cover what only a real model can get wrong: asking before teaching, adapting, not repeating facts, drawing valid data, citing honestly. Rules that plain code decides (sign-in, settings, deck storage) are left to the unit tests.

6. Known gaps

Profile pass qualityThe research note's eval set is not built: passing mood stored as nothing, sensitive detail ignored, contradiction becomes UPDATE, cleared struggle becomes DELETE, "just start" stored as a teaching preference. Only the repeat cases (PR-08) exist. PR-05 to PR-07 and PR-09 to PR-10 have none.
Flashcard generationNo eval that the agent refuses to invent cards when no source covers the topic, or that it fixes a rejected deck on resend.
Whiteboard editsMarks, simpler redraw and extend (WB-02, WB-08, WB-11) are not evaluated. Only the first drawing is.
Multi-turn teachingAlmost every case is one or two turns. Nothing checks the agent over a long session or that it uses the earlier turns well.
Judge is thinOne judged check in the whole set. Whether a reply teaches well, at the right level, is not scored.
Only 3 samplesWith 3 samples per case a 1-in-5 failure often passes unseen. Raise --runs before trusting a green result.
